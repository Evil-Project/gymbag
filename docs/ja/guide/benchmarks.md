# ベンチマーク＆パフォーマンス（Caddy / Nginx 比較）

Gymbag は組み込みの Proof-of-Work WAF、カスタム/リモートルール、AI/不審トラフィック検出を有効にした状態でも、高速な HTTPS リバースプロキシとして動作するよう設計されています。

## テスト環境・計測手法

すべてのベンチマークは同一マシン・同一条件下で実施し、**完全に同一の ECDSA P-256 証明書**で TLS 1.3 を終端し、**同一の Go HTTP/1.1 アップストリームサーバー**（`1 KiB` / `1024` バイト応答）へプロキシしました：

| 項目 | 値 |
| :--- | :--- |
| **ハードウェア** | Apple M4 (10コア CPU, 16 GiB RAM) |
| **OS / ランタイム** | macOS 26.6.1 (`darwin/arm64`), Go `1.27.0` |
| **比較対象** | **Gymbag** `v0.1.0`、**Caddy** `v2.11.9`、**Nginx** `1.31.8` |
| **同時接続数** | `64` 並列ワーカー（HTTP/2 は `8` 本の多重化 TCP 接続） |
| **計測時間** | 各シナリオ `2秒` ウォームアップ + `8秒` 本計測（1プロセスずつ単独実行） |
| **アップストリーム調整** | 3製品ともアイドル keep-alive 上限 `1024`、アクセスログ無効化（Nginx `access_log off`、Caddy `level ERROR`） |
| **直接アップストリーム基準** | `143,761 req/s`（平文 HTTP/1.1, p50 `0.342 ms`, p99 `1.817 ms`, エラー `0`） |

## 主な結果まとめ

1. **HTTP/1.1・HTTP/2 ともに Caddy を大きく上回る高速性**：フル WAF 有効状態でも、Gymbag は Caddy より **HTTP/1.1 で +32% 高速**（`72.5k` vs `54.7k`）、**HTTP/2 で +63%〜+69% 高速**（`64.0k–66.1k` vs `39.2k`）であり、メモリ使用量は **30% 少なく**、バイナリサイズは **3.8分の1** です。
2. **C 言語製 Nginx に迫る性能**：メモリ安全な純粋 Go 標準ライブラリ実装でありながら、Nginx の HTTP/1.1 スループットの **85%** を達成し、**p99 テールレイテンシは Nginx の約半分**（`3.14 ms` vs `6.20 ms`）、HTTP/2 では Nginx の **74%** を記録しています。
3. **WAF 検査オーバーヘッドが極小**：`verify 3`（形状検査・既定ブロックルール・シャードレート制限・AI/不審検知）を有効にしても、`protect off` とほぼ同等のスループット（`72.5k` vs `72.5k` RPS）を維持します。
4. **高速エッジ防御**：`/.env` や `/wp-admin` へのプローブを TLS 終端エッジで **140,680 req/s** で遮断し、バックエンドを完全に保護します。

## 高速化アーキテクチャの仕組み

- **統合型ゼロクローン HTTPS パイプライン**：ホスト解決・クライアント IP・HSTS・WebSocket 判定を 1 パスで処理し、`r.WithContext` によるリクエスト複製や中間 Header/Cookie マップの割り当てを排除。
- **ゼロアロケーション Aho-Corasick DFA**：AI ボット、不審 UA、クエリ攻撃トークン、カスタム `user_agent` ルールを大文字小文字無視の完全 ASCII DFA（`O(len(input))`）へ事前コンパイル。
- **O(1) パスマップ＆高速グロブ**：完全一致パスはハッシュマップ、`prefix*` / `*suffix` / `*sub*` は正規表現を使わず高速文字列判定で処理。
- **64 シャード レート制限 & クリアランスキャッシュ**：64 個のキャッシュライン整列シャードによりマルチコア間のロック競合を排除。
- **事前パース済みアップストリーム＆バッファプール**：アップストリーム URL を起動/リロード時に事前パースし、32 KiB バッファを `sync.Pool` で再利用、SSE 等のストリーム応答時のみチャンクフラッシュを実行。
- **静的応答事前レンダリング＆ロックフリー SNI**：マスコット画像・ETag・ブロック HTML を事前生成し、TLS SNI 証明書を `atomic.Pointer` でロックフリー参照。
